# 0.5.1

Released 2026-11-13. In this release `src/` and the shared test helpers match WordPress core trunk
as of [r65466](https://core.trac.wordpress.org/changeset/65466), byte for byte. There are no
breaking changes, and nothing to do before updating.

## Ported from core

| Changeset | Change | Props |
|---|---|---|
| [r65394](https://core.trac.wordpress.org/changeset/65394) | The Site Health checks are methods of `WP_Site_Health` and `WP_Debug_Data`, not functions in `wp-admin/includes/secrets-site-health.php`. The statuses, labels and descriptions are unchanged. The Info section's key is now `wp-secrets-api`, and the results use the blue Security badge. | ericmann, peterwilsoncc, mindctrl |
| [r65395](https://core.trac.wordpress.org/changeset/65395) | The `_wp_secrets_*()` helpers are marked `@access private`. | wildworks |
| [r65466](https://core.trac.wordpress.org/changeset/65466) | `WP_Secret::__construct()`'s `$value` and `WP_Secrets_Cipher::validate_common()`'s `$master_key` are marked `#[\SensitiveParameter]`, so they are redacted from stack traces. | johnbillion |

whyisjake committed r65394 and r65395, and johnbillion committed r65466.

A plugin can't add methods to core's classes, so before 7.2 the plugin registers copies of core's
methods through the `site_status_tests` and `debug_information` filters, under the same test IDs,
labels and Info key. A test in CI fails when core changes one of the originals.

## Fixed

- **`wp secret health` on 7.2.** It loaded the Site Health file that r65394 removed, which is a
  fatal error on a core that ships the API. It now runs core's checks on 7.2 and the plugin's
  copies before 7.2.

## In review in core

Each of these will be ported once committed.

| Ticket | Change | PR |
|---|---|---|
| [#66424](https://core.trac.wordpress.org/ticket/66424) | A failed read of a secret's record, or of the list of secrets, no longer reads as a missing secret or an empty list. | [15974](https://github.com/WordPress/wordpress-develop/pull/15974) |

Seven multisite defects were reported against 7.2 after this release was prepared, from
[#66686](https://core.trac.wordpress.org/ticket/66686) to
[#66692](https://core.trac.wordpress.org/ticket/66692). They affect this release too: network
secrets stored before a single site is converted to multisite, and secrets on installs with more
than one network.

WP-CLI's `wp config create` will generate the key as well
([wp-cli/config-command#235](https://github.com/wp-cli/config-command/pull/235)). Moving the
`wp secret` commands into WP-CLI is proposed in
[wp-cli/entity-command#677](https://github.com/wp-cli/entity-command/issues/677).
