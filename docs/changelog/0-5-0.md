# 0.5.0

Released 2026-11-10. In this release `src/` and the shared test helpers match WordPress core trunk
as of [r65390](https://core.trac.wordpress.org/changeset/65390), byte for byte: what ships
in 7.2 beta 5.

## Before you update

This release has two breaking changes. Both match core from 7.2 beta 5.

**1. `WP_SECRETS_KEY` is required.** Without it, the Secrets API is unavailable: every call that
needs the key returns `secret_key_unavailable`. Until now the key was derived from `LOGGED_IN_KEY`
and `LOGGED_IN_SALT` when `WP_SECRETS_KEY` was not defined. Rotating the salts then locked every
stored secret ([ADR 0016](../decisions/0016-require-wp-secrets-key.md)).

- A site that already defines `WP_SECRETS_KEY` needs to do nothing.
- A site with no stored secrets only needs to add a key. Site Health shows a generated `define()`
  line to paste into `wp-config.php`, and so does `wp secret generate-key`.
- A site that stored secrets under the fallback must move them **before** updating, or they read
  as `secret_key_unavailable` until it does:
  1. Set `WP_SECRETS_KEY` to a new value, from `wp secret generate-key`.
  2. Set `WP_SECRETS_KEY_PREVIOUS` to the old `LOGGED_IN_KEY . LOGGED_IN_SALT`, the two values
     joined together.
  3. Run `wp secret rotate`.
  4. Remove `WP_SECRETS_KEY_PREVIOUS`.

  Nothing is lost if you update first: the root key is left as it was, and the same steps make
  the secrets readable again afterward.

**2. A `secrets.php` drop-in uses `extends`, not `implements`.** `WP_Secrets_Provider`,
`WP_Secrets_Store` and `WP_Secrets_Keyring` are abstract classes now, not interfaces, so a later
release can add a method without breaking every drop-in
([ADR 0017](../decisions/0017-abstract-classes-for-the-extension-points.md)). Change `implements`
to `extends` in your drop-in. Nothing else in the contract changes.

A drop-in that still uses `implements` is **a fatal error on every request**, WP-CLI included. It
does not fail closed: PHP reports it while compiling the drop-in, before WordPress can catch it.
If you copied one of the [examples](../reference/examples.md), take the new version. They extend
the classes.

  [#66399](https://core.trac.wordpress.org/ticket/66399). Props ericmann, peterwilsoncc,
  digitalpritam, ravipatel, Clorith, dhrupo.

## Changed

- **Drop-ins should mark their own sensitive parameters.** Attributes aren't inherited, so a
  keyring's `wrap()` and a provider's `set()` add `#[\SensitiveParameter]` themselves. The
  examples and [`drop-in-example.php`](../reference/drop-in-example.php) do. On PHP 7.4 the
  attribute line is a comment.
- **CI tests the plugin where it runs.** The full suite runs on WordPress 7.1 and the 6.8 floor.
  On trunk, which ships the API, a separate job checks only that the plugin stands down.
